# 04. S3（ファイル保存）

## 0. なぜ S3 を学ぶか

- このアプリのログインには、S3 は**必須ではありません**。
- ただし、次の用途でほぼすべての AWS 構成で使われるため、基本を学ぶ価値があります。
  - ユーザーがアップロードしたファイル（画像など）の保存
  - DB のバックアップ（ダンプファイル）の保管
  - 静的なファイル（画像、PDF）の配布

## 1. 公式ドキュメント

- バケットの作成: https://docs.aws.amazon.com/AmazonS3/latest/userguide/create-bucket-overview.html

- オブジェクトのアップロード: https://docs.aws.amazon.com/AmazonS3/latest/userguide/uploading-an-object-bucket.html

## 2. 基本の概念

| 用語                             | 意味                                                                    | 例えると             |
| -------------------------------- | ----------------------------------------------------------------------- | -------------------- |
| **バケット（bucket）**           | ファイルを入れる箱。**名前は世界で一意**で、**作成後に変えられない**    | 倉庫の名前           |
| **オブジェクト（object）**       | 保存されるファイル 1 つ                                                 | 倉庫の中の荷物       |
| **キー（key）**                  | オブジェクトの名前（パス）。`images/logo.png` のように `/` を含められる | 荷物の住所ラベル     |
| **リージョン**                   | バケットを置く地域。**作成後に変えられない**                            | 倉庫のある都市       |
| **ストレージクラス**             | 保存の種類（頻繁に使う/めったに使わない など）。料金が変わる            | 近い倉庫か遠い倉庫か |
| **バージョニング**               | 上書き・削除の前の版を残す設定                                          | 上書き前の控えを残す |
| **パブリックアクセスのブロック** | 誤って公開されるのを防ぐ、4 つのスイッチ                                | 倉庫の鍵             |

**フォルダの正体**: S3 には本当のフォルダはありません。キーに `/` を含むと、コンソールがフォルダのように表示します。

## 3. なぜ「公開しない」が基本か

- S3 のバケットを公開すると、**誰でもインターネットから読める**（設定次第では書き込めることもある）。
- 過去には、設定ミスで大量の個人情報が公開された事故が多く起きています。
- そのため、**新しいバケットは既定で「パブリックアクセスのブロック」が 4 つとも有効**になっています（公式の記載）。
- 公開が必要な場合（画像の配布など）は、**CloudFront という配布の仕組みを経由**し、バケットそのものは公開しないのが基本です。

## 4. 手順 A：バケットを作る

**手順（コンソール）**

1. **S3 → Create bucket**。
2. **Bucket name**: `login-app-files-<自分の識別子>-<ランダムな数字>`（例: `login-app-files-taro-20261121`）。
   - 名前のルール: 小文字・数字・ハイフンのみ、3〜63 文字。
   - **名前に個人情報（メールアドレスなど）を入れない**（公式の注意）。
3. **AWS Region**: `ap-southeast-2`（プロジェクトのリージョン）。
4. **Object Ownership**: **ACLs disabled（推奨）**（既定）。
5. **Block Public Access settings for this bucket**: **Block all public access（すべてブロック）にチェック**（既定のまま）。
6. **Bucket Versioning**: **Enable（有効）**（後で説明する理由で、学習では有効にする）。
7. **Default encryption（既定の暗号化）**: 既定のまま（SSE-S3）。
8. **Tags**: `Project=login-app`、`Env=learning`。
9. **Create bucket**。

**CLI**

```bash
REGION=ap-southeast-2
BUCKET=login-app-files-taro-20261121   # 世界で一意な名前に置き換える

# 1) バケットを作る（us-east-1 以外のリージョンでは LocationConstraint が必要）
aws s3api create-bucket --bucket $BUCKET --region $REGION \
  --create-bucket-configuration LocationConstraint=$REGION

# 2) パブリックアクセスを 4 つとも遮断する（念のため明示する）
aws s3api put-public-access-block --bucket $BUCKET --public-access-block-configuration \
  BlockPublicAcls=true,IgnorePublicAcls=true,BlockPublicPolicy=true,RestrictPublicBuckets=true

# 3) バージョニングを有効にする
aws s3api put-bucket-versioning --bucket $BUCKET \
  --versioning-configuration Status=Enabled

# 4) タグを付ける
aws s3api put-bucket-tagging --bucket $BUCKET \
  --tagging 'TagSet=[{Key=Project,Value=login-app},{Key=Env,Value=learning}]'
```

## 5. 手順 B：ファイルを操作して、仕組みを体験する

```bash
# テストファイルを作る
echo "hello v1" > test.txt

# アップロード
aws s3 cp test.txt s3://$BUCKET/test.txt

# 一覧
aws s3 ls s3://$BUCKET/

# 上書きする（内容を変えてもう一度アップロード）
echo "hello v2" > test.txt
aws s3 cp test.txt s3://$BUCKET/test.txt

# バージョン一覧（v1 が残っている）
aws s3api list-object-versions --bucket $BUCKET --prefix test.txt \
  --query 'Versions[].{Id:VersionId,Latest:IsLatest,Modified:LastModified}' --output table

# 古い版をダウンロードする（VersionId は上の表の値に置き換える）
aws s3api get-object --bucket $BUCKET --key test.txt --version-id <VersionId> old.txt
cat old.txt   # hello v1 が表示される
```

**なぜこの練習をするか**: 「上書きしても、古い版から戻せる」という安心を、自分の手で確かめるため。

## 6. 手順 C：削除の挙動を確かめる（バージョニングの本当の意味）

```bash
aws s3 rm s3://$BUCKET/test.txt
aws s3 ls s3://$BUCKET/      # 見えなくなる（最新版に「削除マーカー」が付く）
aws s3api list-object-versions --bucket $BUCKET --prefix test.txt   # 実体は残っている
```

**理解のポイント**: バージョニングが有効なとき、`rm` は「削除マーカー」を付けるだけで、古い版は残ります。**完全に消すには、版を指定して削除する**必要があります。

## 7. 手順 D：ライフサイクルで古い版を自動で消す（料金対策）

**なぜ**: バージョニングを有効にすると、古い版が増え続けて料金が増えるため。

**コンソール**: バケット → Management → Create lifecycle rule。

- 名前: `expire-old-versions`
- Noncurrent versions（古い版）: **90 日後に削除**

**CLI**

```bash
cat > lifecycle.json <<'EOF'
{
  "Rules": [{
    "ID": "expire-old-versions",
    "Status": "Enabled",
    "Filter": {},
    "NoncurrentVersionExpiration": { "NoncurrentDays": 90 }
  }]
}
EOF
aws s3api put-bucket-lifecycle-configuration --bucket $BUCKET \
  --lifecycle-configuration file://lifecycle.json
```

## 8. ストレージクラス（料金の選び方）

公式の記載の要点です。

| クラス                     | 向いている用途                 | 注意                                            |
| -------------------------- | ------------------------------ | ----------------------------------------------- |
| **S3 Standard**（既定）    | 頻繁にアクセスするファイル     | 最も割高。ただし取り出し料金が無い              |
| **S3 Standard-IA**         | 月に数回しか読まないファイル   | **最低保存期間**（30 日）と、取り出し料金がある |
| **S3 Intelligent-Tiering** | アクセス頻度が読めないファイル | 取り出し料金は無いが、監視料金がかかる          |
| **S3 Glacier 系**          | 長期保管（ほぼ読まない）       | 取り出しに時間と料金がかかる                    |

**学習の推奨**: 最初は **S3 Standard のまま**でよい。慣れてから、ライフサイクルで Standard-IA に移すことを検討する。

> 「最低保存期間」を早く消すと、その分の料金を請求されます。ストレージクラスを変えるときは、必ず公式ページで条件を確認してください。

## 9. アクセス権限（誰が読めるか）

- 基本は **IAM ポリシー**で、アプリや人に必要な操作だけを許す。
- 例: アプリには `s3:GetObject` と `s3:PutObject` だけを、特定のバケットに対してだけ許す。

**最小権限の例（アプリ用・参考）**

```json
{
  "Version": "2012-10-17",
  "Statement": [
    {
      "Effect": "Allow",
      "Action": ["s3:GetObject", "s3:PutObject"],
      "Resource": "arn:aws:s3:::login-app-files-taro-20261121/*"
    }
  ]
}
```

**やってはいけない設定**

- `"Principal": "*"` と書くバケットポリシー（誰でも読める）。
- 「すべてのバケットに対する `s3:*`」の付与。

## 10. 運用

| 作業                                               | 頻度    | 理由                           |
| -------------------------------------------------- | ------- | ------------------------------ |
| パブリックアクセスのブロックが 4 つとも有効か確認  | 月 1 回 | 設定の変更による公開事故を防ぐ |
| ライフサイクルの効果を確認（古い版が減っているか） | 月 1 回 | 料金が膨らむのを防ぐ           |
| 使っていないバケットを削除                         | 随時    | 残すと混乱と料金の元になる     |
| Cost Explorer で S3 の料金を確認                   | 毎週    | 想定外の保存量に気づくため     |

**バケットを空にしてから消す**: 中身があるバケットは消せません。バージョニングが有効な場合は、**すべての版と削除マーカーを消す**必要があります。

```bash
# 中身をすべて消す（版も含む）。実行前に必ず対象のバケット名を確認する
aws s3 rm s3://$BUCKET --recursive
aws s3api delete-objects --bucket $BUCKET --delete \
  "$(aws s3api list-object-versions --bucket $BUCKET \
     --query '{Objects: Versions[].{Key:Key,VersionId:VersionId}}' --output json)"
aws s3api delete-bucket --bucket $BUCKET --region $REGION
```

> **注意**: `delete-objects` は版を指定して消すため、取り消せません。実行前に、残したいデータがないかを必ず確認してください。
