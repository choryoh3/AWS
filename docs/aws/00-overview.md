# 00. 全体像と用語集

## 1. このアプリを AWS に載せると、どうなるか

ユーザーがログイン画面を開き、認証コードのメールを受け取ってログインするまでの流れを、AWS の部品で表すと次のようになります。

```
            ユーザーのブラウザ
                  │ https://（公開 URL）
                  ▼
  ┌──────────────────────────────────────────┐
  │ Amplify Hosting（Next.js アプリ）          │  ← 環境変数・シークレットを設定
  └──────────────────────────────────────────┘
          │ ①メール送信（SMTP 587）     │ ②データの読み書き（PostgreSQL 5432）
          ▼                             ▼
  ┌──────────────────┐        ┌─────────────────────────────────────┐
  │ SES               │        │ VPC（自分専用のネットワーク）          │
  │ 認証コードのメール  │        │   private subnet                    │
  │ を送る             │        │     RDS for PostgreSQL（DB）         │
  └──────────────────┘        └─────────────────────────────────────┘

  学習・運用用（任意）
   ・EC2（仮想サーバー）: SSM Session Manager で安全に入り、DB に接続する踏み台
   ・S3（ファイル置き場）: 画像などのファイル、DB のバックアップ置き場
```

**ポイント**

- アプリの**入口**（Amplify）は、インターネットから見える場所に置く。
- DB（RDS）は**インターネットから直接見えない場所**に置く。アプリと、限られた踏み台だけがつながる。
- メール（SES）は、アプリからだけ使えるように、**専用の認証情報**で送る。

> **要確認**: Amplify Hosting から、VPC の中にある非公開の RDS に直接つなぐには、追加の設定が必要になることがあります。本番で構成を決める前に、Amplify の「VPC への接続」の機能を公式ドキュメントで確認してください。学習段階では、EC2 から `psql` で DB に入る練習を優先してください。

## 2. 作る順番と、その理由

| 順番 | 作るもの                              | 理由                                                                  |
| ---- | ------------------------------------- | --------------------------------------------------------------------- |
| 1    | アカウント・MFA・利用上限・予算       | お金と安全の土台。事故を防ぐ安全網                                    |
| 2    | VPC・サブネット・セキュリティグループ | DB とサーバーを置く「家」と「門」。先に決めないと、後で作り直しになる |
| 3    | EC2（踏み台）                         | DB に安全に入る道具。DB の確認に必要                                  |
| 4    | S3                                    | 単独で作れる。ファイル保存の練習                                      |
| 5    | RDS（PostgreSQL）                     | 家（VPC）と門（SG）ができてから作る                                   |
| 6    | SES                                   | ドメイン検証・DNS の設定が必要で、時間がかかる（審査もある）          |
| 7    | アプリの公開（Amplify）               | 上のすべてができてから、環境変数を入れて公開する                      |

## 3. 用語集

| 用語                                  | 意味（ひとことで）                                                                                   | 例えると                      |
| ------------------------------------- | ---------------------------------------------------------------------------------------------------- | ----------------------------- |
| **AWS アカウント / プロジェクト**     | AWS の利用単位。課金・権限の境界。簡易版では「プロジェクト」と呼ばれ、中に AWS アカウントが 1 つ入る | 会社の口座                    |
| **AWS Builder ID**                    | サインインに使う個人の ID。簡易版では、これがプロジェクトの持ち主になる                              | 会員証                        |
| **リージョン**                        | AWS のデータセンターの地域（例: ap-southeast-2 はシドニー）                                          | 建物がある都市                |
| **アベイラビリティーゾーン（AZ）**    | リージョン内の、独立した電源・回線を持つ建物のまとまり                                               | 同じ都市の別のビル            |
| **VPC**                               | 自分専用の仮想ネットワーク                                                                           | 自分専用の敷地                |
| **サブネット**                        | VPC を区切った一区画。1 つの AZ に属する                                                             | 敷地内の区画                  |
| **インターネットゲートウェイ（IGW）** | VPC とインターネットをつなぐ出入口                                                                   | 敷地の門                      |
| **ルートテーブル**                    | 通信の行き先を決める地図                                                                             | 道案内                        |
| **セキュリティグループ（SG）**        | 出入りを許可するルールの集まり（許可のみ・状態を覚える）                                             | 玄関の鍵リスト                |
| **EC2**                               | 仮想サーバー                                                                                         | レンタルの小さな PC           |
| **AMI**                               | EC2 を作るときの OS のひな形                                                                         | OS のインストールディスク     |
| **EBS**                               | EC2 のディスク                                                                                       | PC の SSD                     |
| **SSM Session Manager**               | ポートを開けずに、サーバーに安全に入る仕組み                                                         | 鍵のいらない裏口（認証付き）  |
| **IAM**                               | 誰が何をしてよいかを決める仕組み                                                                     | 社員証と権限表                |
| **IAM ロール**                        | サーバーなどに付ける権限の束                                                                         | 作業者に渡す入館証            |
| **S3**                                | ファイルを保存する場所（バケット）                                                                   | 無限に使える倉庫              |
| **バケット**                          | S3 の保存場所の単位。名前は世界で一意                                                                | 倉庫の名前                    |
| **バージョニング**                    | ファイルの古い版を残す設定                                                                           | 上書き前の控えを残す          |
| **RDS**                               | マネージドのデータベース（バックアップ・更新の一部を AWS が行う）                                    | DB の管理を代行してくれる業者 |
| **DB サブネットグループ**             | RDS を置いてよいサブネットの一覧                                                                     | DB を置いてよい区画リスト     |
| **スナップショット**                  | ある時点のデータの写し                                                                               | 保存用のコピー                |
| **SES**                               | メールを送るサービス                                                                                 | 郵便局                        |
| **SMTP**                              | メールを送るときの決まりごと（通信の方式）                                                           | 郵便の宛名の書き方            |
| **サンドボックス（SES）**             | 最初の制限付きモード。検証済みの宛先にしか送れない                                                   | 試用期間                      |
| **DKIM / SPF / DMARC**                | 「このメールは本当にこのドメインから送った」と証明する DNS の記録                                    | 封筒の本人証明                |
| **利用上限（spend limit）**           | 1 か月に使ってよい上限額。達すると、プロジェクトのリソースが止まる                                   | 小遣いの上限                  |
| **AWS Budgets（予算）**               | 費用の目安を決めて、通知を受け取る仕組み                                                             | 家計簿のアラーム              |
| **Cost Explorer**                     | 費用をサービス別に分析する画面                                                                       | 家計簿の分析                  |
| **タグ**                              | リソースに付けるラベル（例: Project=login-app）                                                      | 荷物の付箋                    |
| **CloudWatch**                        | 監視（CPU・ディスク容量など）と、アラーム                                                            | 健康診断の機械                |
| **CloudTrail**                        | 「誰がいつ何をしたか」の記録                                                                         | 防犯カメラ                    |
| **Secrets Manager**                   | パスワードなどの秘密の値を安全に保管する                                                             | 金庫                          |
| **Amplify Hosting**                   | Web アプリ（Next.js など）を公開するサービス                                                         | 店舗の看板とレジ              |

## 4. 安全の原則（全体で守ること）

1. **ルールは「必要なものだけ許す」**。インターネット全体（`0.0.0.0/0`）に、DB や SSH のポートを開けない。
2. **秘密の値（パスワード・キー・SMTP 認証情報）は、Git や環境変数の平文欄に置かない。** Secrets Manager か、アプリ基盤のシークレット機能に入れる。
3. **日常の作業は、ルートや管理者の権限で行わない**（簡易版では、Builder ID を守ることが最重要）。
4. **作ったものには必ずタグを付け、用途を残す**（後で「これは何？」と迷わないため）。
5. **使い終わったら止める、または消す**（料金は「動いている間」だけでなく、「置いてある間」も発生するものがある）。
