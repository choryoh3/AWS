# 01. アカウント・MFA・利用上限・予算

## 0. なぜこの章が最初か

AWS は「使った分だけ課金される」仕組みです。設定を誤ると、気づかないうちに請求が増えたり、第三者に乗っ取られたりします。**お金と安全の守りを先に固める**のが、この章の目的です。

## 1. 公式ドキュメント

- Sign up for AWS (new): https://docs.aws.amazon.com/accounts/latest/reference/sign-in-new.html
- Compare sign-up options: https://docs.aws.amazon.com/accounts/latest/reference/sign-up-for-aws.html
- Supported AWS services for Sign up for AWS (new): https://docs.aws.amazon.com/accounts/latest/reference/supported-services-sign-up-new.html
- AWS Regions for your projects: https://docs.aws.amazon.com/accounts/latest/reference/project-regions.html
- Create a spend limit in AWS Settings: https://docs.aws.amazon.com/accounts/latest/reference/create-spend-limit.html

## 2. 簡易版（Sign up for AWS (new)）の仕組み

**なぜ簡易版か**: このガイドは、本番の構成を少ない手間で学ぶための入口です。通常版（advanced）は設定項目が多く、初心者には負担が大きいため、まずは簡易版で練習します。

**簡易版の特徴（公式ページで確認した内容）**

| 項目                | 内容                                                                                         | 初心者へのポイント                                          |
| ------------------- | -------------------------------------------------------------------------------------------- | ----------------------------------------------------------- |
| サインイン          | Google / GitHub / Apple / Amazon のいずれかのログインを使う                                  | 普段使うアカウントを 1 つ決めて、それを使い続ける           |
| 持ち主の ID         | **AWS Builder ID** がプロジェクトを所有する。**ルートユーザーは作られない**                  | Builder ID を守ることが、そのままアカウントを守ることになる |
| 単位                | **プロジェクト**（中に AWS アカウントが 1 つ入る）                                           | 「プロジェクト」が、ここで言う AWS アカウント               |
| 設定画面            | **AWS Settings**（https://settings.aws.com）                                                 | MFA・連絡先・利用上限はここで設定する                       |
| IAM                 | IAM ユーザーは作れるが、**プログラムからのアクセスにしか使えない**（コンソールには入れない） | 人が入る権限は、Builder ID 側で管理する                     |
| IAM Identity Center | 自動で有効になる                                                                             | 追加の設定は不要                                            |

**無料枠（Free Tier）と有料プラン**

- 無料枠では、EC2・RDS・SES・Amplify・Budgets・IAM・Secrets Manager・S3・VPC などが使える（公式の対応サービス一覧に含まれる）。
- **利用上限（spend limit）を作るには、有料プランへのアップグレードが必要。** 本ガイドの「利用上限」の手順は、有料プランにしてから行う。
- 有料プランにするとき、クレジットカードなどの支払い方法を登録する。公式ページには「USD $1 相当を 3〜5 日間保留して、本人確認をする」と書かれています。

## 3. 手順 1：サインアップ

1. 上の公式ページ「Sign up for AWS (new)」を開き、**普段使うログイン**（Google など）でサインアップする。
2. 名前・連絡先のメール（ログインのメールの確認コード）・パスワード・連絡先（住所の国）を入力する。
3. **連絡先の国**は、後述のリージョンの決まり方に影響する。正確に入力する。

**なぜ**: 連絡先の国で、プロジェクトのリージョンが自動で決まるため。

## 4. 手順 2：リージョンを確認する

**リージョンは選べません。** 公式ページの記載では、連絡先の国に応じて次のいずれかに割り当てられます。

| 連絡先の地域 | 割り当てられるリージョン                 |
| ------------ | ---------------------------------------- |
| 米国         | US East (Ohio) — `us-east-2`             |
| ヨーロッパ   | Europe (Stockholm) — `eu-north-1`        |
| アジア太平洋 | Asia Pacific (Sydney) — `ap-southeast-2` |

- 日本の連絡先は「アジア太平洋」に含まれるため、`ap-southeast-2`（シドニー）になる**見込み**です。
- **確認方法**: AWS Settings → Project → Overview で「Region」を確認する。
- 連絡先を後で変えても、リージョンは変わらない（公式の記載）。

**なぜ**: リージョンはデータの置き場所であり、後から変えにくい。SES の SMTP 認証情報も、リージョンごとに作り直す必要があるため、最初に確認する。

**CLI で確認する**

```bash
aws configure list          # 現在のプロファイルのリージョンが表示される
aws configure set region ap-southeast-2   # 違うときは、ここで合わせる（ap-southeast-2 はプロジェクトの値に置き換える）
```

## 5. 手順 3：MFA（多要素認証）を登録する

**なぜ**: パスワードだけでは、漏えいや推測で乗っ取られる危険があります。MFA を付けると、スマートフォンの認証コードなどが無いと入れなくなります。

**手順**

1. AWS Settings を開く（https://settings.aws.com）。
2. 自分の Builder ID（または、サインインのアカウント）の、セキュリティ（MFA）の画面を開く。
3. 認証アプリ（例: 認証アプリケーション）を登録する。QR コードを読み取り、表示された 6 桁を入力して確認する。
4. **予備の MFA を別の端末に登録する。** 1 台を失くすと入れなくなるため。

> **要確認**: MFA の画面の名称と手順は、公式ページ「Manage multi-factor authentication (MFA) in AWS Settings」で確認してください。

## 6. 手順 4：利用上限（spend limit）を設定する

**利用上限とは**: 1 か月にプロジェクトが使ってよい、税抜きの上限額です。上限に達すると、プロジェクトのリソースが**停止されます**。

**公式ページの要点**

- 有料プランでのみ作れる。
- 最低額は **$20 か、それ以上の見積もり額のうち大きい方**。見積もりは、今月の利用と、動いているリソースから計算される。
- 上限は**プロジェクトごと**に設定する。
- クレジットは対象外（税抜きの請求額が対象）。
- 通知は、実際の費用が上限の **50%・75%・90%** に達したときと、10 日以内に上限を超えそうなときに届く。
- 上限に達すると、プロジェクトは**一時停止**される（学習用・サンドボックス向けの仕組み）。

**なぜ設定するか**: 設定ミス（例：EC2 を付けっぱなし）で、請求が膨らむのを防ぐ最後の安全網になるため。

**手順（コンソール）**

1. 有料プランへアップグレードする（AWS Settings の Billing の画面から）。
2. AWS Settings → Billing → 対象のプロジェクトの **Spend limit** から、上限額（$20 以上）を設定する。
3. 通知メールのアドレスを確認する。

**注意（学習中の挙動）**

- 上限に達すると、EC2 や RDS が停止される。**停止されても、データが消えるとは限らない**が、動かなくなるので注意する。
- 上限に近づいたら、使っていないリソースを先に止める（07 章の運用を参照）。

## 7. 手順 5：予算（Budgets）を作る

**利用上限とは別の、早めの警告です。** 利用上限が「止める仕組み」なのに対し、予算は「気づかせる仕組み」です。

**公式ページの要点**: 「Spend limits are a type of AWS Budgets（利用上限は、AWS Budgets の一種）」と書かれています。AWS Budgets は、対応サービス一覧にも含まれています。

**手順（コンソール）**

1. AWS の Billing and Cost Management（請求の画面）を開く。
2. Budgets → Create budget。
3. 種類は「Cost budget（コストの予算）」を選ぶ。
4. 月額の予算は **$20**、通知は **80%**（実際の費用）と **100%**（予測）に設定する。
5. 通知先のメールアドレスを入力する。

> **要確認**: 簡易版で Budgets の画面が使えるかは、実際の画面で確かめてください（対応サービス一覧では「AWS Budgets」は含まれています）。

## 8. 手順 6：CLI をインストールして、接続を確認する

**なぜ CLI を使うか**: 同じ作業を、記録として残せる（手順書にそのまま書ける）。画面を探す手間が減る。

**CLI のバージョン**

- `aws signup` は AWS CLI **2.41.0 以降**で使える。
- `aws login` は **2.32.0 以降**で使える。

**インストール**

- AWS 公式の「Installing or updating to the latest version of the AWS CLI」を開き、お使いの OS の手順に従う。

**サインインと接続確認**

```bash
# 新しくサインアップする場合（ブラウザが開く）
aws signup

# すでにプロジェクトがある場合（ブラウザでプロジェクトを選ぶ）
aws login

# 接続確認：自分のアカウント ID が表示されれば成功
aws sts get-caller-identity
```

**よくある注意**

- `aws login` / `aws signup` は**ブラウザでの操作が必要**。コマンドを実行したまま、ブラウザで完了させる。
- 認証情報は自動で更新される（簡易版の仕組み）。ただし、**このファイルや Git に認証情報を書かない**。

## 9. 費用を確認する場所

| 見る場所                                 | 何がわかるか                 | 見る頻度       |
| ---------------------------------------- | ---------------------------- | -------------- |
| Billing and Cost Management → Bills      | 今月の請求の内訳             | 毎週           |
| Cost Explorer                            | サービス別・日別の費用の推移 | 毎週           |
| AWS Settings → Billing（プロジェクト別） | 利用上限と、今月の利用の割合 | 毎週           |
| 予算の通知メール                         | 予算に近づいたかどうか       | 届いたら即確認 |

**なぜ**: 「気づいた時には高額」を防ぐため。毎週の確認は、07 章の運用で再度まとめます。
