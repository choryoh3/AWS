# AWS 入門ハンズオン（簡易版アカウントから始める）

本番環境の作成は、すべて人間が行う。AWS の画面は頻繁に変わるため、手順の細部は必ず公式ページで確認すること。

> **注意**: この手順書の「簡易版（new）」の部分は、公式ページを直接読んで確認できていません（作成時点でこの環境から `docs.aws.amazon.com` に接続できなかったため）。ユーザーからの情報をもとに書いており、**「要確認」の項目は、実際の画面と公式ページで必ず確かめてから進めてください。**

## 0. 公式ドキュメント（最初に読む）

- Sign up for AWS (new) — 簡易版（new）のサインアップの流れと、AWS Builder ID の作り方
  https://docs.aws.amazon.com/accounts/latest/reference/sign-in-new.html
- Compare sign-up options — 簡易版と通常版（advanced）の違い。簡易版でできないことはここで確認
  https://docs.aws.amazon.com/accounts/latest/reference/sign-up-for-aws.html

### 簡易版（new）と通常版（advanced）の主な違い（ユーザーからの情報）

- **サインインの中心は AWS Builder ID**。通常版のような「ルートユーザー」を前提にした手順ではない。
- 画面（UI/UX）も通常版と異なる部分がある。メニュー名や場所は、この手順書の記載と違うことがある。
- 利用上限は **$20**（アカウントプラン）。上限まで使うと、利用が止まるか、追加の操作が必要になる（上限の挙動は要確認）。

### Builder ID について

- 開発者向けツールや、簡易版アカウントへのサインインに使う**個人向けの ID**。
- AWS アカウントそのものとは別の仕組みとして説明されている。作成手順は上の「Sign up for AWS (new)」に従う。

## 1. 簡易版アカウントを作り、サインインを安全にする

1. 上の「Sign up for AWS (new)」の手順で、AWS Builder ID を作り、簡易版のアカウントを作成する。
2. **Builder ID（サインインの ID）に多要素認証（MFA）を設定する。** 画面の案内に従う（設定できる方式と場所は要確認）。
3. **利用上限（$20）と現在のプランを確認する。** 請求の画面（Billing）で、アカウントプランと上限、残りの利用枠を確認する。どこまでが簡易版で使えないかは「Compare sign-up options」で確かめる。
4. **予算アラートを作る**（AWS Budgets）。簡易版で Budgets を使えるかは要確認。使えるなら、月額 $20 の予算を作り、80% で通知メールが届くようにする。使えない場合は、請求画面の利用状況を毎週見る運用にする。
5. リージョンは **東京（ap-northeast-1）** を基本にする（簡易版で選べるリージョンは要確認）。

## 2. 日常の作業用の権限を決める

- 簡易版でも IAM Identity Center などの「学習用の権限」を使えるかは要確認。使えない場合は、サインインに使うアカウントだけで作業し、他人と共有しない。
- 作業用の認証情報は、画面に表示された手順で作り、**Git や環境変数の平文欄には入れない**。

## 3. CLI を入れて接続を確認する（要確認）

簡易版でも CLI でアクセスできるかは要確認。できる場合は次のように確認する。

```bash
aws configure sso          # 画面で案内される方式でプロファイルを作る（入力項目は要確認）
aws sts get-caller-identity --profile <プロファイル名>   # 自分のアカウントが表示されれば接続 OK
```

## 4. ストレージ（S3）を触る

1. バケットを作る（名前は世界で一意）。**パブリックアクセスは「すべてブロック」のまま。**
2. ファイルをアップロードし、バージョニングを有効にして、上書きしたときの動きを確かめる。
3. CLI でも操作する（CLI が使える場合）: `aws s3 cp ./test.txt s3://<バケット名>/`

## 5. 権限（IAM）を理解する

1. ポリシー（JSON）を読み、「どの操作をどのリソースに許すか」を説明できるようにする。
2. 最小権限の原則: 必要な操作だけを許す。簡易版で IAM を作れるかは要確認。作れない場合は、ポリシーの読み方の学習だけを行う。

## 6. ネットワーク（VPC）とサーバー（EC2）

1. 既定の VPC、サブネット、セキュリティグループの役割を確認する。
2. 小さなインスタンス（t3.micro または t4g.micro。無料枠の対象かは請求画面で確認）を起動する。簡易版で EC2 を起動できる地域・種類は要確認。
3. 接続は SSH より **Session Manager** を使う（ポートを開けずに済む）。
4. **使い終わったら停止、または削除する。** 停止しても EBS などの料金は残る点に注意する。

## 7. データベース（RDS for PostgreSQL）

1. RDS で PostgreSQL（16 系）を作る。学習用は小さなクラス（db.t4g.micro）で、パブリックアクセスは「なし」。簡易版で RDS を作れるかは要確認。
2. EC2 から `psql` で接続し、テーブルを作って確かめる。
3. **学習が終わったら削除する。** RDS は停止しても一定期間後に自動で再開されるため、放置するとコストが増える。

## 8. メール送信（SES）

このアプリの認証コードは SES の SMTP で送る（`SMTP_HOST=email-smtp.<リージョン>.amazonaws.com`、587 番）。簡易版で SES を使えるかは要確認。

1. SES で送信元のメールアドレス（または独自ドメイン）を **検証** する。
2. 「SMTP 設定」で SMTP 認証情報を作る。**この値は秘密情報。** Git や環境変数の平文欄には入れず、Secrets Manager か Amplify のシークレットに置く。
3. **サンドボックス** の間は、検証済みの宛先にしか送れない。本番では「本番アクセス」を申請する。
4. 送信テスト後、受信箱（迷惑メールも含む）で確認する。

## 9. アプリを公開する（最初の 1 回）

学習用の第一候補は **AWS Amplify Hosting**（Git リポジトリを接続し、Next.js の SSR を扱える）。簡易版で使えるかは要確認。

1. GitHub リポジトリを Amplify に接続し、`apps/web` を対象にする。
2. 環境変数を設定する（`docs/setup.md` の一覧。`BETTER_AUTH_URL` は公開 URL に変える）。
3. 秘密の値（`BETTER_AUTH_SECRET`、`SMTP_PASS`、`DATABASE_URL`）はシークレットとして登録する。
4. 本番の DB に接続する前に、マイグレーションを `pnpm --filter @app/db db:migrate` で適用する（接続先を本番の値にして、人間が実行する）。
